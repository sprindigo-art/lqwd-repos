## Spacing Scale

8-point scale (all multiples of 4). Existing status page uses `p-8`/`px-3 py-2`/`gap-1` — keep consistent.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, badge inner padding, dot-to-grade gap in a row |
| sm | 8px | Compact element spacing, chip gaps, dimension cell padding |
| md | 16px | Default element spacing, card inner padding, gap between dimension cells |
| lg | 24px | Section padding, gap between scorecard sections |
| xl | 32px | Page padding (`p-8`), gap between overview header and table |
| 2xl | 48px | Major section breaks (overview ↔ per-node detail) |
| 3xl | 64px | Page-level top/bottom breathing room on wide layouts |

**Exceptions:** none. Table cells follow `px-3 py-2` (12px / 8px) — 12px is a multiple of 4 and matches the Phase 1 status-page convention; keep it for table density.

## Typography

Three roles + display. System sans; **exactly 4 sizes** (24 / 20 / 16 / 14px) and **exactly 2 weights** (400 regular, 600 semibold).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display (page title) | 24px (`text-2xl`) | 600 semibold | 1.2 |
| Heading (node alias / section) | 20px (`text-xl`) | 600 semibold | 1.2 |
| Body (grades, reason subtext, raw values) | 16px (`text-base`) | 400 regular | 1.5 |
| Label (table headers, badges, chips, freshness stamp, % suffix) | 14px (`text-sm`) | 600 semibold (labels/badges) / 400 (subtext) | 1.4 |

**Rules:**
- All numeric values (percentages, PPM, sats, channel counts) use `tabular-nums` so columns align (carry forward from status page).
- Letter grade glyph (A/B/C/D/F) renders at body size, weight 600, to read as a strong signal next to the color dot.
- Reason subtext renders at 14px, weight 400, `text-foreground/70` (muted) — secondary to the grade.
- Uppercase table headers and chips stay on the **14px Label role**; their smaller optical feel is achieved with `uppercase` + `tracking-wide` (letter-spacing), NOT a separate smaller font size. There is no 12px type size in this contract.

> Note: the page title (H1) renders at 24px / weight 600 — the 24px size alone provides the display differentiation, so no third weight (700/bold) is needed. The entire contract uses only two weights: 600 semibold (display, headings, labels, badges) and 400 regular (body, subtext).

## Color

LQWD brand is **navy `#1A3C79`** — NOT Bitcoin orange `#F7931A` (LOCKED, CLAUDE.md + memory). Dark theme default. Tokens already declared in `globals.css` `@theme`; this phase formalizes the **status/grade palette** as named tokens so grade colors are not hardcoded inline (the status page's inline `style={{color:"#1A3C79"}}` is the pattern to REPLACE with tokens).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0b0e14` (`--background`) | App background, table body, card surfaces |
| Secondary (30%) | `#11151f` cards / `#1A3C79` (`--color-brand`) navy for table header band + structural chrome | Card backgrounds, table header row, section dividers (`border-white/10`) |
| Accent (10%) | `#1A3C79` → `#2A5299` (`--color-brand` / `--color-brand-light`) | Navy is **brand/structural chrome only** — table header band, backend=LND badge, primary section emphasis, focus rings, links. NOT used to signal node health. |
| Destructive | (no destructive ACTION in Phase 2) | Phase 2 is read-only — no destructive controls. `#dc2626`-class red is reserved exclusively for the **Tier-1 critical health signal** (see below), not for any button/action. |

**Accent reserved for:** table header band, the LND backend badge, focus rings, internal links/affordances, and primary structural emphasis. Navy is explicitly NOT a health-status color — it must never be confused with the green/yellow/red health system.

### Health status palette (the load-bearing color contract — D-05, D-07)

This is the critical, operator-hard-ruled distinction. **Two perceptually distinct color systems coexist and must never blur:** brand navy (chrome) vs. the green/yellow/red health signal.

| Status token | Value (suggested; dark-theme-tuned) | Meaning | Where it appears |
|--------------|--------------------------------------|---------|------------------|
| `--status-ok` (🟢) | `#22c55e` | All-clear — no Tier-1 breach AND grade healthy | Node color dot, dimension dot, grade A/B |
| `--status-warn` (🟡) | `#eab308` | Warn-level only — caps here, **never escalates to red on its own** | Node color dot when ≥1 dim is non-healthy but NO Tier-1 breach; dimension dot for C/D grades |
| `--status-critical` (🔴) | `#dc2626` | **Tier-1 critical breach ONLY** (D-07/D-08) | Node color dot iff ≥1 dimension hits Tier-1; the separate critical chip |
| `--status-nodata` (grey) | `#6b7280` (`text-foreground/40`) | "no data — needs log ingestion" (D-01) — distinct from any real grade | The 3 log-fed dimensions (stability, PG health, visibility); excluded from rollup |
| `--status-stale` (amber-grey, muted) | `#a16207` muted / dashed outline | Data past staleness threshold (D-13) | Per-node stale marker (node still shown) |
| `--status-outlier` (neutral marker, NOT red) | `#8b5cf6` violet OR a neutral ◆ glyph | MAD outlier / worst-in-fleet (D-12) — a SEPARATE signal that does NOT alter grade/color | Separate outlier marker badge on a dimension/row |

**HARD operator rules encoded in color (D-07 — verbatim: *"we certainly can't have any issue lead to a red badge making it appear critical"*):**
1. **Red (🔴) is reserved for genuine Tier-1 critical breaches ONLY.** A node is 🔴 if and only if ≥1 dimension hits its `tier1` line (fee crash <10 PPM, AP-11 close-storm ≥50/hr, node unreachable/`num_peers==0`+stale, PG FATAL[no-data in P2]).
2. **Warn-level issues cap at yellow (🟡).** No accumulation of Tier-2/3 issues, and no low composite grade, may ever turn the node dot red.
3. The **Tier-1 breach renders as a SEPARATE critical chip** (e.g. `🔴 critical: fee crash`) — it is NOT folded into the composite letter grade/percentage. A critical problem is never diluted by 9 healthy dimensions; a minor issue never masquerades as critical.
4. The **MAD outlier marker is a third, separate signal** (D-12) — uses the neutral/violet outlier token, NOT red, and does NOT change the absolute grade or the dot color.
5. **"No data" (grey) must be visually unmistakable from a real grade** (D-01) — greyed, with an explicit "needs log ingestion" label, and excluded from the rollup math.

> Accessibility: color is never the SOLE carrier. Every status pairs color + a letter grade and/or a text label (the operator explicitly asked for grade/% because "3 colors alone are too vague"). The critical chip carries its `tier1.label` text. "No data" and "stale" carry text labels. This satisfies non-color-dependent perception.

## Layout & Interaction Contract (phase-specific — derives from D-05/D-06/D-09/D-10/D-13)

### Fleet overview row (FLEET-01) — shadcn `table`
Concrete shape (operator-described, LOCKED):
```
[🟢🟡🔴 dot] [LDK|LND badge] Alias — [GradeGlyph] [pct]% — "reason subtext" [🔴 critical chip?] [⚠ stale?] [◆ outlier?]   data as of {asOf}
```
Verbatim operator examples this MUST reproduce:
- `France — 🔴 C 68% — "critical: fee crash"`  (red dot + separate critical chip)
- `Sweden — 🟡 B 84% — "low revenue"`           (yellow dot, no chip)
- `Canada — 🟢 A 91%`                            (green dot, no reason needed)

Columns: status dot · backend badge · alias · composite grade glyph · composite % · reason subtext · conditional critical chip · freshness stamp (+ conditional stale marker) · conditional outlier marker.

**Sort order (D-09, LOCKED):** criticals first (any node with a Tier-1 breach), then worst composite grade first (triage order). Default sort applied server-side in the RSC before render.

### Per-node 10-dimension scorecard (FLEET-02) — shadcn `card`
- Show **all 10 dimensions** (D-01). Layout: a responsive grid of dimension cells (recommend 2-col on `md`, 1-col stacked on small screens; up to 3-col on `xl`).
- **Each computable dimension cell (D-05):** `{dimension name} {🟢🟡🔴 dot} {GradeGlyph} {pct}% — {raw value}` — e.g. `Revenue 🟢 B 88% — 84 PPM`. Color = instant scan, grade/% = detail, raw value = the evidence.
- **The 3 no-data dimensions (D-01):** rendered greyed with `no data — needs log ingestion` label; visually distinct from a graded cell; excluded from the rollup. Partial peer dimension (#7) renders its computable value + a `partial — flap-rate needs event history` note.
- **Composite header (D-06):** composite grade glyph + % (unweighted mean of available dims) + reason subtext + the separate critical chip if any. Reason = the Tier-1 breach if one exists, else the lowest-grade non-healthy dimension.
- **Cross-node read (D-10/D-11/D-12):** each dimension additionally shows a peer-relative read (vs per-backend cohort median) and a separate outlier marker if MAD-flagged. Small cohort → `no peer baseline yet` (D-11). Outlier marker NEVER changes the absolute grade.

### Freshness (D-13) — every node, every view
- A "data as of {worst-case oldest timestamp}" stamp on each node (FLEET-01 + scorecard).
- Past the tunable staleness threshold, a **stale marker** (`⚠ stale`) — node remains visible, not hidden. This state is **frequent and real** (Germany ~10mo old, several nodes Dec 2025) — design it as a first-class state, not an edge case. Tooltip on the stamp shows the per-table breakdown.

### Responsive behavior
- Overview table: horizontal scroll on narrow (`overflow-x-auto`, carry-forward), but keep status dot + alias + grade always visible (sticky leading columns acceptable).
- Scorecard grid: collapses 3→2→1 columns down the breakpoints.

### States required (every data view)
- **Loading:** RSC + `force-dynamic` (no client spinner needed for first paint); if a `'use client'` chart is added, give it a fixed height to avoid SSR zero-size flash.
- **Empty (no nodes):** see Copywriting Contract.
- **Error (warehouse unreachable):** Phase 1 boot health-check fails loud; for in-page degradation, see Copywriting Contract.
- **No-data dimension / no-peer-baseline / stale:** all explicit, labeled, honest (fail-loud ethos) — never silently blank.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"View scorecard"** — the overview row's primary affordance (navigates to the per-node 10-dimension scorecard). Phase 2 is read-only; this is navigation, not a write action. |

| Empty state body | **"No nodes were returned from the routing warehouse. Confirm `ROUTING_VM_DATABASE_URL` points at `routing_vm` and the read-only role has SELECT access, then reload."** |
| Error state | **"Couldn't load fleet health."** — body: **"The routing warehouse didn't respond. Your data is unchanged — this view is read-only. Check the warehouse connection and reload."** |
| No-data dimension | **"No data — needs log ingestion"** (stability, PG health, visibility) — tooltip: **"This signal lives in node/PG logs, not the warehouse. Excluded from the health rollup until log ingestion is added."** |
| Partial dimension (peer) | **"Partial — flap-rate needs event history"** — tooltip: **"Current peer count is live; per-peer flap rate needs disconnect-event history we don't yet collect."** |
| No peer baseline | **"No peer baseline yet"** — tooltip: **"Too few nodes of this backend for a stable peer comparison."** (D-11, fires for the ~1-node LDK cohort) |
| Stale marker | **"⚠ Stale — data as of {date}"** — tooltip: **"This node's grade rests on data older than the freshness threshold. Shown anyway, flagged so you know."** |
| Critical chip | **"🔴 critical: {tier1.label}"** — e.g. `critical: fee crash`, `critical: close storm`, `critical: unreachable`. Plain-English Tier-1 label, never a raw code. |
| Outlier marker | **"◆ Worst-in-fleet"** / **"◆ Outlier"** — tooltip: **"More than N MADs from the {backend} cohort median on this dimension. This does not change the grade."** |
| Destructive confirmation | **N/A — Phase 2 has no destructive (or any) write action.** Read-only by design (HARDEN/READ trust boundary). No confirmation flows exist this phase. |

**Tone:** terse, operator-facing, fail-loud and honest about gaps (matches project ethos). Never present stale or missing data as authoritative.
