# Phase 17 — UI Design Contract

> Visual and interaction contract for the Incident Detail view (INC-01), incident tracking
> lifecycle (INC-02), and the AI explanation layer (AIX-01 / AIX-02). Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase COMPOSES the locked Data-Forward (df) v2 design system (Phase 10/12) — it invents
> no new design language.** Nearly every visual primitive already exists in `src/components/df/*`
> and is byte-locked to the Ops Center v2 prototype snapshot. The contract below is prescriptive
> about *which existing primitives compose into each surface* and *what net-new UI (tracking
> controls, snoozed-critical banner, verdict badge, on-demand read wrapper) must match*.

## Spacing Scale

The df system is a **prototype-locked** system built byte-perfect off the Ops Center v2 snapshot.
Baseline grid is Tailwind's 4px unit; the prototype carries a small set of **sanctioned off-grid
values** (accent bars, tight radii, optical paddings) that are part of the locked contract, not
drift. New Phase-17 UI uses the on-grid scale; it reuses off-grid values ONLY when composing an
existing primitive that already ships them.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, chip inner gaps (`gap-1`) |
| sm | 8px | Compact element spacing, control gaps (`gap-2`) |
| md | 12–16px | Default element spacing, card inner padding rows (`gap-3` / `p-4`) |
| lg | 24px | Card padding (`p-6`), section padding |
| xl | 28–32px | Expand-grid column gap (`gap-7`), major layout gaps |
| 2xl | 48px | Major section breaks between the five page regions |

Exceptions (locked, from the prototype — reuse verbatim, do NOT normalize):
- **7px** hero left accent bar; **3px** severity section-bar / row left border (`.sectionbar`, DS-01 state marker).
- Radii: **3px / 6px / 9px / 14px / 18px** via `--radius-df-pill|btn|card|card-lg` — "instruments, not bubbles".
- Optical type paddings inside primitives (e.g. `pb-[14px]` WhyChain rows, `ps-[31px]` expand grid) — internal to locked primitives.

## Typography

Three locked typefaces; **two working weights** carry the phase (600 semibold + 700 bold for
emphasis; 400 regular for body). The df system uses a fixed role ladder rather than a 3–4 size
token set — the phase-relevant roles are declared below (all sizes are locked prototype values).

| Role | Font | Size | Weight | Line Height | Usage |
|------|------|------|--------|-------------|-------|
| Incident headline | Inter (sans) | 23px | 700 | 1.18 | Incident Detail status-header title (reuses `SeverityHeroCard` h2 grammar) |
| Body / narrative | Inter (sans) | 14.5px | 400 | 1.55 (relaxed) | AI read prose, incident narrative, `max-w-62ch` |
| Data / label | IBM Plex Mono | 11–13px | 400 / 600 | 1.45 | Host ids, timestamps, meta chips, tracking-state stamps (`tabular-nums` for counts) |
| Eyebrow / kicker | IBM Plex Mono | 9.5–11.5px | 700 | 1 | UPPERCASE section eyebrows, `tracking-[0.07–0.14em]` (blast-radius, why-chain, verdict labels) |

Rules (locked, sketch findings): mono carries ALL data and labels; **no emoji, no state dots-as-icons**
(severity is a 3px border + tinted label, never a glyph). `df-faint` (#9AA3B4) is DECORATIVE-only —
never load-bearing text (fails AA); load-bearing text uses `df-ink` / `df-muted`.

## Color

The df system splits color into **two set-disjoint families**: navy **chrome/brand** (structure &
affordance) and the **severity ramp** (state). Severity is NEVER navy; navy is NEVER a health color.
This is the DS-01 invariant and is non-negotiable for every Phase-17 surface.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-df-bg` #EEF1F5 (page ground) + `--color-df-surface` #FFFFFF (cards) | Incident Detail page background + all card surfaces |
| Secondary (30%) | `--color-df-chrome` #13284F (navy) + `--color-df-border` #E4E7EE hairlines | Nav rail, the AI-read panel surface, structural borders |
| Accent (10%) | `--color-df-brand` #1A3C79 | See reserved-for list below |
| State: critical | `--color-df-critical` #E0392B (+ tint #FCEBEA / border #F3D3D0) | Critical incident severity, blast-radius edges, "Act now" verdict |
| State: warning | `--color-df-warning` #C8770A (+ tint/border) | Warning severity, "Monitor" verdict |
| State: watch | `--color-df-watch` #0E8C84 teal (+ tint/border) | Watch severity, "Informational" verdict |
| State: ok | `--color-df-ok` #1E9E63 (non-text) / `--color-df-ok-text` #1E7A4E (text) | Resolution callouts, "data fresh" dot |
| State: stale | `--color-df-stale-*` #A9912F text / #C8A23A square dot | Honest stale — shape-distinct (square dot + dashed border), never a softened green |

**Accent (navy) reserved for — explicit list (never "all interactive elements"):**
- Focus rings / text selection (`--ring` #2C5CB4 / brand).
- Active nav-rail item and active facet filter.
- The `.act` / primary structural buttons (e.g. the on-demand "explain" trigger, the ack/assign/snooze controls' active/hover state).
- Links and affordances on light surfaces (`--color-df-brand`).
- The AI-read panel's navy chrome surface (`bg-df-chrome`) — structure, explicitly NOT a severity hue.

**Destructive:** `--destructive` exists in the base theme but **Phase 17 has NO destructive actions.**
INC-02 is tracking-only (zero-write-path to the fleet, project invariant). Ack / assign-to-me / snooze
are reversible metadata writes to the `nodemon` queue DB — they mutate nothing on any node and require
no destructive-confirm dialog. The one consequential path — snoozing a **critical** — is guarded by the
persistent snoozed-critical banner (D-04) + escalation-breakthrough (D-06), **not** a modal.

## Blast-Radius Containment-Tree Spec (D-08)

**Reuse `df/BlastRadius.tsx` verbatim.** It is already the locked containment diagram — a single
root-cause host card fanning out to N impacted target nodes via dashed animated edges. It is
pure props-driven SVG (SSR-safe, no Recharts, no network-graph lib — satisfies the D-08 "no new
graph viz lib" constraint).

| Aspect | Contract |
|--------|----------|
| Structure | Host card at root (left) → dashed edges → target pills (right column), 1..N targets auto-centered. This IS the containment tree (host → affected nodes → channel/HTLC risk notes). |
| Severity tinting | Critical red `#E0392B` (`DF.critical`) edges + host hairline; target pills wash `#FCEFEE` / border `#F1D1CD` / muted-red note `#9A5B55`. Literal hexes (SVG can't resolve CSS vars SSR-safely) — matches `StaleChart` precedent. |
| Root eyebrow | "ROOT CAUSE · FIX HERE" in `DF.faint` #9AA3B4 (decorative). Wrap in the hero's "Blast radius" section eyebrow (`SeverityHeroCard` blast region) for the detail page. |
| Per-target note | HTLC-at-risk / channel-state line under each node id (mono id + note). |
| Motion | `v2flow` dashed-edge animation (existing keyframe); static under reduced-motion/print (dash pattern still reads). |
| A11y | `role="img"` + `aria-label="Blast radius: {host} affecting N nodes"` (already built in). |
| Data source | Targets derive from the `assembleIncidents` host→node→channel/HTLC tree — NOT re-derived in the component. |

**Do NOT** introduce a force-directed / D3 / react-flow graph. The containment tree is the locked answer.

## Why-Chain / Detection-Timeline Spec (D-09)

**Reuse `df/WhyChain.tsx` verbatim.** One element = the why-chain AND the timeline (D-09): a single
vertical dot-and-line spine, oldest→newest top-to-bottom, each event carrying its detection time.

| Aspect | Contract |
|--------|----------|
| Element | ONE vertical spine. Each event = a severity-colored 9px dot + connecting line + mono timestamp + event sentence. Last connector transparent (clean terminus). |
| Causal order | Events ordered root cause → downstream effect → impact (each step a `WhyChainEvent { time, text, severity }`). Order mirrors the payload's causal chain; do not reorder in the view. |

| Placement | Above the blast-radius diagram per D-10 (status header → AI read → why-chain → blast-radius → grouped children). |

## AI-Read Panel Spec (AIX-01 / D-13 / D-15)

**Reuse `df/AiReadPanel.tsx` on the navy `bg-df-chrome` surface**, triggered on-demand (D-12), dismissed
session-only (D-15). The panel already carries the frozen, caller-immutable safety copy — do NOT
override it:
- `AI_SAFETY_LABEL` = "AI · explains & ranks, never runs commands"
- `AI_ZERO_CREDENTIAL_NOTE` = "NodeMonitor runs nothing for you."
- Body renders as INERT `whitespace-pre-wrap` plain text (React-escaped; no `dangerouslySetInnerHTML`, no markdown-to-HTML). This is the injection-containment contract — keep it.

### Verdict badge (D-13) — the net-new addition

The read must **lead with exactly one urgency verdict** on its own line before the prose. Render it as
a df severity chip (mono uppercase, tinted, `severityAccent[sev]` background, white text) sitting at the
top of the panel content, above the explanation prose.

| Verdict label | Maps to Severity | Chip token | Meaning |
|---------------|------------------|-----------|---------|
| **Act now** | `critical` | `df-critical` #E0392B tint/accent | Genuine outage — investigate immediately. |
| **Monitor** | `warning` | `df-warning` #C8770A | Real but not emergency — keep watching. |
| **Informational** | `watch` | `df-watch` #0E8C84 teal | Benign / self-healing / stale-but-healthy. |

Rules:
- Verdict vocabulary is advisory-only and adjustable at implementation as long as it stays command-free (D-13, Claude's discretion). Default set above.
- The verdict chip NEVER uses navy (navy = chrome, not state). It reads the severity ramp only.
- The verdict is derived from the deterministic payload's `worstSeverity`, not the model's mood (AI-SPEC verdict-vs-severity cross-check). If the model verdict is below the payload severity, the panel still renders but the mismatch is flagged upstream (AI-SPEC guardrail) — the UI must not visually "downgrade" a critical.
- **Never renders a runnable command.** No code block, no `lncli`/`systemctl`, no numbered "do X" (guardrail post-check owns this; the panel's plain-text render is the last line of defense).

### Trigger + dismiss (D-12 / D-15)

- **Trigger:** an on-demand button in the AI-read region — reuse `NarrateButton` grammar (mono uppercase, `text-df-brand`, hairline border, tight 3px radius). Idle label: `EXPLAIN — LLM`; pending: `READING…`. Visible only when the LLM flag is on, but visibility is NOT the gate (the server action re-checks `isLlmEnabled()`).
- **Degradation:** if the read fails/withheld/flag-off, the deterministic incident cards stand alone — the panel is simply absent (never blocks the page render). Error copy: see Copywriting.
- **Dismiss:** session-only via the `AiReadPanel` `onDismiss` ✕ wrapped in an `AiBandClient`-style `useState(false)` — NO persistence (a reload re-derives it). Matches D-15.
- **AIX-02 rationale:** the one-line "why these alerts grouped" narration reuses the `AiReadLine { sev, head, body }` shape (no `action` field, by construction) and shows on BOTH overview and incident detail.

## Tracking-Control Spec (INC-02 / D-02..D-06)

A single client control cluster in the status header. **Tracking-only — zero writes to the fleet.**
Navy is the affordance/active color; severity ramp is never used for the controls themselves (only
for the incident's own severity chip).

| Control | Decision | UI contract | States |
|---------|----------|-------------|--------|
| **Acknowledge** | D-05 | Single toggle button (`.act` grammar). On ack: shows ✓ + owner id + relative time stamp (mono). Ack **sorts the incident lower but keeps it visible** in the overview queue — never hides. | `un-acked` (navy outline `.act`) → `acked` (✓ stamp: "ack'd · {owner} · {age}"). |
| **Assign to me** | D-02 | Solo toggle "Assign to me" / "Unassign" (single operator id — no named list, no free-text). | `unassigned` → `assigned (you)` (navy-filled active). |
| **Snooze** | D-03 | Fixed-preset segmented control: `1h` · `4h` · `24h` (mono, `tabular-nums`). No custom time picker. Snoozing removes the incident from the main queue. | `active` → `snoozed until {time}` chip with an "un-snooze" affordance. |
| **Escalation breakthrough** | D-06 | Not a control — a state rule the UI must reflect: a NEW critical child clears ack AND snooze and re-surfaces the incident at top as critical. The controls reset to their un-acked/un-snoozed state on breakthrough. | mute cleared → back to `un-acked` / `active`. |
| **Recurrence** | D-07 | A resolved-then-refailed host is a brand-new incident with fresh state (ack/owner/snooze reset). UI treats it as new, not a re-open. | fresh incident, empty tracking state. |

**Interaction feel:** controls use `useTransition` optimistic pending like `NarrateButton`; reversible,
no confirm dialog (nothing destructive). Mono uppercase labels, hairline borders, 3–9px radii.

## Snoozed-Critical Banner Spec (D-04)

The honesty mechanism: **snooze declutters but never fully hides a critical.**

| Aspect | Contract |
|--------|----------|
| Presence | Persistent, always-visible, **fleet-wide** (shows on overview AND incident detail) whenever ≥1 critical is snoozed. Zero snoozed criticals → banner absent. |
| Copy | "N snoozed critical" — e.g. `2 snoozed critical incidents — muted, not resolved`. Count in mono `tabular-nums`. Clicking reveals/links to the snoozed criticals. |
| Color | Critical severity ramp (`df-critical` tint/border/text) — this is a state surface, so it wears the ramp, NOT navy. Left 3px critical border per `.sectionbar` grammar. |
| Placement | Above the fold, sticky at the top of the queue / detail chrome so it can never scroll out of sight. |
| Non-dismissible | Unlike the AI read, this banner has NO dismiss — muting a critical must remain visible until un-snoozed or resolved (D-04 invariant). |

## Accessibility

- **Color is never the sole signal (DS-01):** severity carries a 3px border/label + mono word (`severityLabel`) alongside hue; stale is SHAPE-distinct (square dot + dashed border), not just a color shift. Verdict badges pair the ramp color with the explicit word ("Act now" etc.).
- **Contrast:** load-bearing text uses `df-ink` #10131A / `df-muted` #6F7787 (AA); `df-faint` #9AA3B4 is decorative-only and never carries meaning. `df-ok` uses the AA-text variant `df-ok-text` for labels. AI-read prose is white/`#CBD6EC` on navy `#13284F` (AA).
- **SVG semantics:** `BlastRadius` has `role="img"` + descriptive `aria-label`; decorative dots/rects are `aria-hidden`.
- **Controls:** ack/assign/snooze are real `<button>`s with `aria-pressed`/`aria-expanded` where toggling; snooze presets are a labeled group. AI dismiss ✕ has `aria-label="Dismiss AI read"`.
- **Motion:** `v2flow` / `v2pulse` animations degrade to static under `prefers-reduced-motion` / print — the dashed edge and critical ring still read without motion.
- **Focus:** brand ring `--ring` #2C5CB4 (navy chrome) on all interactive elements; no severity hue on focus.
- **Keyboard:** collapsible child-alert groups use native `<details>`/`<summary>` (keyboard-operable by default); each child row's deep link (D-11) is a real `<a>`.
