# Phase 6 — UI Design Contract

> Visual and interaction contract for the Command Queue + Approval UI (Prong 1). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase adds NO new design system, tokens, fonts, or colors.** It reuses the operator-validated NOC Light system sealed in Phases 2–5 (sketch-findings-nodemonitor, validated 2026-06-11). The contract below restates the binding tokens and prescribes the copy + interaction grammar for the four new surfaces: the **enqueue preview/confirm leaf**, the **`/queue` page**, the **approval panel** (with stale-ack checkbox), and the **audit timeline**. Source of every token: `src/app/globals.css` + sketch-findings-nodemonitor (do not redefine).

## Typography

Sizes restricted to the established Tailwind scale already in use (`text-xs` for all mono data/controls is the dominant size in this phase — it is the instrument density the operator approved). Exactly 2 weights: regular (400) + semibold (600). No new sizes introduced.

| Role | Size | Weight | Line Height | Font |
|------|------|--------|-------------|------|
| Body | 16px (`text-base`) | 400 | 1.5 | Inter (`--font-sans`) |
| Data / control / label | 12px (`text-xs`) | 400 / 600 (controls, keys) | ~1.4 (`leading-5` on `<pre>`) | IBM Plex Mono (`--font-mono`), uppercase + `tracking-[0.14em]` for controls |
| Heading (section/panel-head) | 20px (`text-xl`) | 600 | 1.2 | Saira Semi Condensed (`--font-display`), uppercase letterspaced |
| Display (page title) | 28px (`text-3xl`) | 600 | 1.2 | Saira Semi Condensed (`--font-display`) |

All ppm/sat/msat/timelock values render through `@/lib/format/units.ts` (AFM-002) with `tabular-nums` — never inline `/1e8` or `*1000`. Diff numbers are mono `text-xs tabular-nums` per the `CommandExport` context-row precedent.

## Color

Restates the NOC Light contract from `globals.css` (`:root`) + `@theme`. Navy is structural chrome only; severity is the only state color; **no new color introduced this phase**.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#eef1f7` (`--background`) | Page ground for `/queue` |
| Secondary (30%) | `#ffffff` (`--card`) / `#f4f7fc` (`--secondary`/`--muted`/panel surfaces) | Command rows, panel surfaces, the preview/diff/timeline panels |
| Accent (10%) | `#1A3C79` (`--primary`/brand) + bright `#2C5CB4` (`--ring`/`--color-brand-glow`) | See reserved list below |
| Destructive / critical | `#D92638` (`--color-status-critical`) + `-dim` tint `rgba(217,38,56,0.08)` | Reject action affordance, expired/failed state chips, stale-gate warning |

**Accent (navy) reserved for — explicit list, never "all interactive elements":**
- `:focus-visible` ring on controls (`--ring` `#2C5CB4`) — the existing `CommandExport` affordance.
- Page/section header chrome and the `/queue` active-nav state in the masthead.
- The CONFIRM ENQUEUE and APPROVE control text/affordance (navy = the deliberate brand-chrome act; it is **not** a health signal).
- Deep links / `open {tab} →` style affordances (`--color-brand-glow`), matching the Active Signals `.go` link.
- Sparkline strokes if any policy-history micro-viz is rendered (navy `#2C5CB4`) — optional, not required.

**Severity tokens (state only, never navy):**
- `--color-status-ok` `#0B8A51` — `succeeded` state, COPIED confirmation echo.
- `--color-status-warn` `#8F5D00` — stale-data acknowledgement warning, `safety:` prefix, COPY-FAILED.
- `--color-status-critical` `#D92638` — `rejected`/`failed`/`expired` terminal chips, the reject affordance, the stale-blocked gate.
- `--color-status-stale` `#5D6A80` — past-freshness-band stamp; `pending_approval`/`claimed`/`executing` in-flight states render in muted/foreground neutral (no severity hue until terminal).

State→chip mapping (mono uppercase letters in a severity-tinted chip, the GradeBadge/CriticalChip grammar — **no dots, no icons**):
`PENDING_APPROVAL` neutral · `APPROVED` neutral/navy · `CLAIMED`·`EXECUTING` neutral muted · `SUCCEEDED` ok-green · `REJECTED`·`FAILED`·`EXPIRED` critical-red.

## Copywriting Contract

Voice = the established mono-uppercase control voice (`export commands` / `COPY` / `safety:`) and the Phase 5 "expanding is inert, the explicit control is the act" grammar (D-02). Controls are lowercase-on-trigger, UPPERCASE-on-commit, matching `CommandExport`.

| Element | Copy |
|---------|------|
| Enqueue trigger (collapsed) | `enqueue fee update` |
| Enqueue trigger (expanded) | `hide preview` |
| Primary CTA (the deliberate write act) | `CONFIRM ENQUEUE` |
| Preview intent labels (mono key/value rows) | `node` · `channel` · `current → proposed ppm` · `base fee (msat)` · `timelock delta` · `expires` (the computed `expires_at`, +24h) · `bounds` (min–max echo when a param is edited) |
| Operator-override marker | `OVERRIDDEN` chip (warn-tinted) shown inline beside any param the operator nudged off the engine's suggested value — recorded to audit per D-03 |
| Enqueue success | `QUEUED — PENDING APPROVAL` (mono, ok-green, the `COPIED`-style in-place echo) |
| Approve CTA | `APPROVE` (navy) — requires the confirm gesture (D-07) |
| Reject CTA | `REJECT` (critical-red) — requires the confirm gesture (D-07) |
| Reject reason field | label `reason (optional)`, placeholder `why is this being rejected?` — free text, rendered as a text node only (never an HTML sink), captured to audit when provided (D-07) |
| Stale-data gate (blocked-by-default, D-10) | Warning line (warn-tinted): `data is stale — last fetched {asOf}. approve is blocked until acknowledged.` · Checkbox label: `I acknowledge the data is stale` · APPROVE stays disabled until checked; the ack is written to the audit row. |
| Empty state heading (`/queue`, no commands) | `QUEUE IS EMPTY` |
| Empty state body | `No fee-update intents have been enqueued. Enqueue one from a fee recommendation on the Inbox or a node console.` |
| Empty state body (suppressed-only nodes) | `Nodes flagged for a close-storm or connection issue have fee actions suppressed — no enqueue control appears for them.` (mirrors INSIGHT-06) |
| Error state — enqueue failed | `COULD NOT QUEUE — {reason}. Nothing was written. Try again, or check the node's HMAC secret is configured.` (server-action error shape from `narrate.ts`) |
| Error state — approve/reject lost race | `THIS COMMAND IS NO LONGER PENDING APPROVAL — it was already approved, rejected, or expired. Reload the queue.` (the `state=<expected>` guard failed, RESEARCH Pattern 4) |
| Error state — missing per-node secret | `NO SIGNING SECRET FOR THIS NODE — set NODEMON_HMAC_SECRET_<pubkey> and retry. The intent was not queued.` |
| Timeline empty (should never happen post-enqueue) | `No transitions recorded.` |
| LDK-backed `update_fee` card — unsupported enqueue state | Rendered in place of the enqueue control (where `enqueue fee update` would otherwise sit), as a non-interactive warn-tinted mono line (`--color-status-warn`, `text-xs` uppercase mono, hairline, no chip/dot/icon, no actionable affordance): `LDK fee enqueue not yet supported — deferred to Phase 7`. Server-resolved (`backendFor(pubkey) === "ldk"`); no CTA, no expand. Source: CONTEXT D-01b. |

**Destructive / irreversible actions (each requires the explicit confirm gesture — no auto-run, D-02/D-07):**

| Action | Confirmation copy |
|--------|-------------------|
| CONFIRM ENQUEUE | `Sign and queue this fee update? It will sign immutably and wait for your approval. Confirm to write.` (the write + HMAC signature is immutable after this; only state flips afterward — D-04) |
| APPROVE | `Approve this fee update for execution? Only approved commands become execution-eligible.` |
| APPROVE (stale override) | gated additionally behind the `I acknowledge the data is stale` checkbox before the confirm is enabled (D-10) |
| REJECT | `Reject this command? This is terminal — it cannot be re-approved.` |

No node mutation occurs in this phase — confirmations describe queue-state effects only (the stub executor, not a real node, drives post-approval states; there is **no operator "simulate" control** per D-13).
