<objective>
Build the enqueue write path UI: the server actions (enqueueCommand/approveCommand/rejectCommand, narrate.ts shape — server re-validates, never accepts a client signature) and the EnqueuePreview client leaf (expand to inert preview, editable-within-bounds, CONFIRM ENQUEUE), mounted on update_fee cards on BOTH surfaces (the /inbox InsightCardRow and the console ActiveSignalsPanel).

Purpose: QUEUE-01 — the operator enqueues an update_fee intent from a recommendation card; it lands pending_approval and does nothing until approved. The control mirrors the Phase 5 inline-expand (one component, both surfaces, D-01); expanding is inert, CONFIRM ENQUEUE is the deliberate write act (D-02). Suppressed cards carry null actions upstream, so the control is simply absent (no new guard). Additionally, the enqueue control is gated to LND-backed nodes only — `backendFor(pubkey) === "lnd"` (the Phase 2 backend resolver in `src/lib/config/backends.ts`, `server-only`); LDK-backed cards render an honest unsupported state instead of the enqueue action (RESEARCH Open Question 2 RESOLVED; project core value — never enqueue an action no node can execute). The three actions also serve plan 06's approval surface.
Output: queue server actions plus EnqueuePreview leaf plus both mount edits.
</objective>
