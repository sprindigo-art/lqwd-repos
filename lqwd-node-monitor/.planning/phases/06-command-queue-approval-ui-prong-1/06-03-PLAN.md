<objective>
Build the server-only write services for the operator-facing lifecycle: `enqueue` (sign-once + transactional INSERT of a `pending_approval` command and its initial audit row) and `transitions` (`approve`/`reject` transactional flips guarded by `WHERE state=<expected>`, each writing an audit row, with the D-10 stale-ack and D-07 reject reason). Plus the live-nodemon test fixture.

Purpose: This is the operator half of the state machine (QUEUE-01 enqueue, QUEUE-03 approve/reject + audit). Every flip is atomic (`UPDATE … WHERE id=? AND state=<expected>` + audit insert in one `dbNodemon.transaction()`), making it idempotent and surfacing the "no longer pending" lost-race. The signature is immutable from enqueue; approval merely flips state (D-04).
Output: enqueue + transitions modules + their live-nodemon integration tests + shared fixture, green.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator intent → enqueue | Validated update_fee params cross server-side before sign+write |
| concurrent approvals → transitions | Two operators/tabs could race the same pending row |
| reject reason → audit | Free-text operator input stored as data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-08 | Tampering | Lost-update race on approve | mitigate | `UPDATE … WHERE id=? AND state='pending_approval'` returning + zero-row throw makes the flip idempotent; a second approve fails cleanly (RESEARCH §Pattern 4) |
| T-06-09 | Repudiation | Untracked state change | mitigate | Every flip writes a command_audit row (from/to/actor/ts/staleAck/reason) in the SAME transaction — no flip without an audit trail (D-08) |
| T-06-10 | Tampering | Stale-data approval (decision integrity) | mitigate | staleAck recorded into audit (D-10); the UI gate (06-05) blocks-by-default until acknowledged; the diff reads LIVE policy (06-05) |
| T-06-11 | Spoofing | Client-supplied signed payload | mitigate | enqueue recomputes command_id/expires_at/canonical/signature server-side; client never supplies the signature (narrate.ts precedent, CLAUDE.md §5) |
| T-06-12 | Injection | Reject reason as HTML sink | mitigate | reason stored + rendered as a text node only (V5); never an HTML/markdown sink |
| T-06-SC | Tampering | npm installs | mitigate | Zero installs this phase |
</threat_model>
