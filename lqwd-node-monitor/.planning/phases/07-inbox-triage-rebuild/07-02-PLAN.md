<objective>
Add the `enqueueBatch` sibling server action that powers bulk-enqueue (INBOX-04). It loops the EXISTING per-row `enqueue()` path once per intent — each in its own transaction, signed once server-side — collecting a best-effort `{ ok | error }` tally with each failure's reason verbatim. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (bulk UI) → enqueueBatch server action | Untrusted `{pubkey, params}[]` crosses here; the action is the authoritative re-validation + signing gate |
| enqueueBatch → enqueue() → nodemon DB (RW) | The only write path; signs once per row server-side with the per-node secret |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-03 | Spoofing/Tampering | client supplies a forged signature/canonical payload in bulk | mitigate | Action accepts `{pubkey, params}[]` ONLY; the per-row `enqueue()` recomputes command_id/expires_at/canonical/signature server-side (CLAUDE.md §5); test asserts no signature field on the input type |
| T-07-04 | Tampering | bulk params outside bounds | mitigate | `enqueueInputSchema` (= `updateFeeBoundsSchema`) re-validates EVERY row server-side before signing; node re-enforces a third time (Phase 8) |
| T-07-05 | DoS (lost work) | one bad row aborting all writes | mitigate | Per-row independent transactions; NO outer tx; best-effort tally keeps good writes (D-07 / Pitfall 1) |
| T-07-06 | Information disclosure | secret bytes in logs/error copy | mitigate | `console.error("enqueueBatch row failed")` with no message; `enqueueErrorCopy` carries no secret bytes (V7) |
| T-07-07 | Tampering | enqueue on AP-11/AP-12 suppressed node | mitigate | Suppressed cards arrive with `suggestedAction === null` → excluded from the selectable set upstream (07-04); enqueueBatch additionally only succeeds with valid params (defense in depth) |
</threat_model>
