<objective>
Build the COL-01 read layer: `getServiceLogEvents(hostId, service|null, window)` over
`service_log_events`, applying the D-04 benign suppression AT READ TIME by LEFT JOINing
`log_patterns_config` ON the event's `config_id` (the matched-pattern primary key) and
dropping rows whose matched pattern has `suppress=true`, ordering newest-first, and mapping
rows to the shipped `NodeLogLine` shape so `NodeLogsStream` (Plan 08) and `ServiceLogTail`
(Plan 08) render real data.

Purpose: this is the read half of "un-stub the log UI". Benign filtering lives here
(not the collector, D-04) so benign rules re-tune with no fleet redeploy. Suppression is
keyed on `config_id` (not `classification`) because classification is a 6-value enum that
does NOT uniquely determine suppress — the `benign` class holds both suppress=true BP-rows
and the suppress=false `SQLSTATE 40001` sibling, and `critical` holds 5 sibling rows; a
classification join would leak BP-001 (suppression inversion) and duplicate a critical event
5× (fan-out). Joining on the config_id primary key is 1:1, so it does neither.
Output: a tested reader + SQL builder mirroring host-metrics.ts, with the one net-new
per-pattern benign-JOIN SQL shape.
</objective>
