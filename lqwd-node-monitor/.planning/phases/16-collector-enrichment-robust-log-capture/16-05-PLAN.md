<objective>
Populate per-node daemon-log paths owner-side and self-maintaining (COL-06, D-07). Create a SEPARATE owner-run reconciler (`scripts/fileserver/path-reconciler.sql`) that first asserts a guarded UNIQUE constraint on `service_inventory (host_id, service_name)` (the live schema has PK `id` only), then UPSERTs the standard fleet-layout `lnd` / `bitcoind` / `postgres` log paths + globs into `service_inventory` for every `hosts` row via a convention-driven `INSERT ... SELECT ... ON CONFLICT DO UPDATE`, and document those standard paths/globs in `db/seed-dimensions.sql` so the reconciler reconciles rather than clobbers the canary-added rows.

Purpose: the canary showed native-probed daemon logs were unregistered, so `extract_events` had nothing to tail (0/8639 PG FATALs captured). D-07 wants paths to self-maintain fleet-wide WITHOUT granting the collector any write — so this is an owner-side artifact, never folded into `collect_telemetry.py` (Pitfall 7). This produces the path surface the capture pipeline (16-02/16-03) reads live each tick.
Output: new `scripts/fileserver/path-reconciler.sql` (owner-run guarded-constraint DDL + UPSERT) + extended `db/seed-dimensions.sql` documenting the daemon paths/globs. No collector code changes; the SELECT-only warehouse boundary is preserved.
