<objective>
Widen and sharpen capture (COL-05): replace the single `error_pattern` substring gate with capture-by-`log_patterns_config`-match, add D-05 tier gating (info=count-only, warn=capped, critical=more) where the tier is the matched row's `classification` value, decouple log-tailing from `detection_method` so native postgres/bitcoind logs are tailed (unifying the existing PG double-tail), and add IP:port normalization so per-peer errors collapse to one signature. Uses the cursor from 16-02.

Purpose: the canary showed 8639 PG FATALs captured as 0, and `[WRN]`/`[CRT]` never captured, because capture gated on one substring and native services were never tailed. Tier gating kills the CMGR/connid exemplar flood while the count always survives (D-06).
Output: refactored `extract_events`, tier-aware exemplar emission, decoupled tailing in `grade_service`/`main()`, and `_RE_IP_PORT` in `_normalize`.

SEQUENCING NOTE: the info/warn/critical tier gating only MATCHES live config after 16-04's owner-run reseed replaces the OLD `benign/ap11/ap12` classification VALUES in log_patterns_config with the info/warn/critical taxonomy. 16-04's reseed SQL MUST be applied (owner-side) before/at canary or info-tier suppression will not match the live rows — see 16-06 CANARY-RUNBOOK section. This plan reads `classification` AS the tier; it does not add a `tier` column.
</objective>
