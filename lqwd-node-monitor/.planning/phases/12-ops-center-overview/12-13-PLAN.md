<objective>
Fix the two taxonomy/grouping BUGS the operator surfaced in live verify, in the
PURE data layer (no UI here). Redesign spec D-R3 (taxonomy fix) + D-R4 (tree-aware
filter):

- **Dedup services** by `(ownerHostId, serviceName)` — collapse the host-level row
  (nodePubkey null) and the per-node duplicate rows of the SAME service into ONE
  child, keeping the worst severity + the most specific reason. Kills the repeated
  "Address List Sync" rows.
- **Attach every service/alert to an owner**, and route the truly-unattributed into
  ONE clearly-labeled "Unattributed" bucket group — NEVER a bare context-free
  top-level incident (operator: orphan rows are "useless").
- **Retain each child's `layer`** so the filter can read the tree.
- **Rewrite `applyFilter`** to match a card when ANY alert in its tree matches the
  layer/severity facet, and to narrow surviving cards' children to matching layers
  when a layer facet is active. This fixes "nodes confused with hosts / nothing
  appears."

Purpose: the queue reads as ONE card per owner with deduped, attributed children,
and the layer filter visibly works. Reuses the tested engine — this is dedup +
attribution + tree matching, NOT a re-derivation of severity/grouping.
Output: a corrected `incidents.ts` assembler + a tree-aware `filter.ts`, both
locked by RED-first tests.
</objective>
