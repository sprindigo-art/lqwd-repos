<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (browser) → server action | untrusted params cross here; the client must send params ONLY, never a signature |
| server action → nodemon queue DB | signed row written; guarded transitions enforce integrity |
| nodemon queue DB → node (out of scope) | node re-verifies HMAC + re-bounds + atomic claim (3rd enforcement) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-03-01 | Spoofing/Tampering | client forges an HMAC or signed params | mitigate | Action input schema accepts { pubkey, params, staleAck } ONLY; enqueue() signs once server-side; test asserts no signature field client-side |
| T-13-03-02 | Tampering | out-of-bounds fee params (the canary set a fee off a stale snapshot) | mitigate | enqueueInputSchema (updateFeeBoundsSchema, ppm 0–5000) re-validated server-side before signing; test rejects out-of-bounds before enqueue |
| T-13-03-03 | Tampering | double-apply / withdraw racing an in-flight claim | mitigate | withdraw() guarded on WHERE state='approved' (D-02); 0 rows ⇒ throw "already claimed"; node-side FOR UPDATE SKIP LOCKED claim unchanged |
| T-13-03-04 | Repudiation | a fee intent lands approved with no trail | mitigate | enqueueAndApprove preserves ∅→pending_approval→approved via enqueue()+approve() (NOT an insert-at-approved bypass); append-only command_audit |
| T-13-03-05 | Elevation | AI emits an executable param | accept/mitigate | params come only from the operator's bounds-clamped edit; no AI import in the action (HARDEN-03 re-affirm) |
| T-13-03-SC | Tampering | npm installs | mitigate | zero new package installs in this plan |

## Canary abuse-case defense (08-04 LQWD-Ireland)
enqueueAndApprove cannot repeat the canary: params are bounds-gated server-side, staleAck is
required to be recorded for a stale baseline (enforced at the UI gate in Plan 06 + audited here),
and the audit trail is preserved so an approved-unclaimed intent is withdrawable via withdraw().
