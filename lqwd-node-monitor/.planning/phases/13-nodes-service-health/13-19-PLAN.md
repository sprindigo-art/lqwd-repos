<mechanism>
Verified against Next.js 16 docs (nextjs.org/docs/app/api-reference/file-conventions/default):
- During SOFT navigation Next.js tracks the active state (subpage) of each parallel
  slot independently. The `(overview)` layout has two slots: the implicit `children`
  and `@modal`.
- `children` resolves `[pubkey]/page.tsx` and its sub-routes. The `@modal` slot has
  ONLY `@modal/default.tsx` (root) plus `@modal/inbox` and `@modal/pending`. It has NO
  `[pubkey]` segment, so on a client-side transition into the `[pubkey]` dynamic
  segment the router cannot reconcile the `@modal` slot at that depth → 404.
- On HARD navigation the whole tree rebuilds from root and the root `@modal/default.tsx`
  satisfies the unmatched slot → works. This is exactly the reversed-symptom (soft 404 /
  hard OK) parallel-route class.
- Minimal fix: add a `default.tsx` INSIDE the slot at the `[pubkey]` segment depth
  returning `null`. Next resolves the nearest `default.tsx` up the slot subtree for any
  deeper unmatched path, so `@modal/[pubkey]/default.tsx` also covers
  `/[pubkey]/channels`, `/[pubkey]/peers`, `/[pubkey]/forwards`, `/[pubkey]/[tab]`, and
  `/[pubkey]/service/[service]`.
</mechanism>
</context>
