## Spacing Scale

*Source: Phase 2 UI-SPEC (unchanged); confirmed against implemented pages.*

8-point scale, all multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, badge inner padding, dot-to-grade gap |
| sm | 8px | Chip gaps, table cell vertical padding, summary-strip cell gaps |
| md | 16px | Card inner padding, gap between summary strip and table, tab-list gaps |
| lg | 24px | Section padding, gap between console header / tab bar / tab panel |
| xl | 32px | Page padding (`p-8` / `py-8`), gap between page header and content |
| 2xl | 48px | Major section breaks (fleet `/pending`: gap between node groups) |
| 3xl | 64px | Page-level breathing room on wide layouts |

**Exceptions:** table cells keep `px-3 py-2` (12px/8px — 12 is a multiple of 4; Phase 1/2 density convention). Pending rows and the 500-row event tables use the same cell rhythm — dense is correct for an operator console.

## Typography

*Source: Phase 2 UI-SPEC, REVISED to formalize the implemented console-label style and unify the micro size (D-04 polish scope). Exactly 4 sizes, exactly 2 weights.*

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display (page/console title, triage-stat numbers, composite grade letter) | 24px (`text-2xl`) | 600 | 1.2 |
| Heading (node alias, section headings, summary-strip values, primary table cell) | 16px (`text-base`) | 600 | 1.3 |
| Body (table cells, reason subtext, tooltips, empty/error body, cap banner) | 14px (`text-sm`) | 400 | 1.5 |
| Console label (column heads, tab labels, stat labels, freshness stamps, badges, window-picker segments) | 12px (`text-xs`) | 600 | 1.3 |

**Rules:**
- **Console label role is always** `font-mono uppercase tracking-[0.14em]` (0.14–0.16em range), muted (`text-foreground/45`–`/55`). This is the implemented console voice — formalized here.
- **Polish action (D-04):** replace every `text-[11px]` with the 12px token (`text-xs`). One micro size, not two. There is no 20px size in this contract — `text-xl` usages from Phase 2 (empty-state headings) drop to Display 24 or Heading 16.
- All numeric values (sats, PPM, counts, ages, percentages) render `font-mono tabular-nums` so columns align. Every sat/BTC/fee value goes through AFM-002 — components receive pre-formatted strings, never raw units.
- Pubkeys render `font-mono` at Body or Console-label size, truncated `{first8}…{last6}`.
- Two weights only: 600 (display, headings, labels, grade letters) and 400 (body, subtext).

## Density Revision — the D-14 contract (REVISES Phase 2 D-05 tile encoding)

*Source: 03-CONTEXT.md D-14 + operator verbatim: "letter grade color percentage all in one line its overkill."*

The grade display unit is simplified fleet-wide during the D-04 polish pass. This is prescriptive:

1. **The grade unit is `dot + letter`. Nothing else.** `🟢 A`, `🟡 B`, `🔴 C`. The percentage is REMOVED from fleet-overview rows and from every dimension tile.
2. **The composite percentage survives in exactly one place:** the scorecard composite header (`B · 84%` next to the composite letter), where the operator drills for detail. Dimension-level percentages move to the tile's tooltip (with the grade-band explanation); they no longer render inline.
3. **Dimension tiles show three things, aligned:** mono label (top-left) · dot+letter (top-right) · raw evidence value (bottom-left, Heading role, AFM-002-formatted). Partial/no-data/outlier notes keep their existing slot. Nothing else on the tile.
4. **Fleet rows show:** dot+letter · alias+backend · reason subtext + chips · freshness. The `%` column dies.
5. **Alignment is a feature:** grade units right-align in their column, evidence values left-align, numerics are tabular. "Aligned items, not over-explained" is the acceptance bar.
6. Reason subtext, critical chips, the outlier marker, and the stale marker are NOT redundant encodings — each carries information the dot+letter does not. They stay.

## Layout & Interaction Contract (phase-specific — D-01..D-13)

### Tabbed console at `/{pubkey}` (D-01, D-02, D-03)
- Tab order: **Scorecard | Channels | Fees | Liquidity | Forwards | Closes | Peers | Pending**. Scorecard is the landing tab; the existing `ScorecardPanel` becomes its content.
- Every tab has a **stable URL** (route segment or query param — planner's discretion, D-03). Deep-linkable; Phase 4 cards will link straight to evidence tabs.
- Tab bar: Console-label typography; active tab gets the navy indicator + full-strength foreground; inactive tabs muted. Keyboard focus visible (`--ring`).
- **Scorecard tiles deep-link to their evidence tab** (D-02): Liquidity tile → Liquidity tab, force-close tile → Closes, revenue/routing → Forwards or Fees as relevant. The tile is the affordance (whole tile clickable, hover border + `text-brand-glow` cue) — consistent with the fleet row pattern.
- The fleet-list quick-look modal stays; it gains an **"Open full console →"** link (Button, link/ghost style, brand-glow hover) to `/{pubkey}`.
- Console header (above tabs): alias + `BackendBadge` + short pubkey + composite dot+letter (+% per D-14 rule 2) + `FreshnessStamp`. LND and LDK render through identical components — no backend branching in layout.

### Event tables — Forwards, Closes (D-05, D-06, D-07) and table tabs generally
- **Window picker:** segmented control `24h | 7d | 30d | 90d`, default **7d** (aligns with scorecard windows so grade and drill-down tell the same story). Four links writing a query param; selected segment carries the navy accent; no custom range.
- **Summary strip** sits ABOVE the table: a horizontal band of stat cells (same visual grammar as the fleet `TriageStat` strip — mono micro-label over a 24px tabular value, `gap-px` cells on a border ground). Contents per table type are planner discretion; the locked mock shape is: Σ count · Σ amount · Σ fees · avg · busiest channel (AFM-002 throughout).
- **Capped rendering:** newest ~500 rows, no pagination, no infinite scroll. Beneath the strip, above the rows, a **cap banner** (Body role, muted, full-width, with the Export CSV button right-aligned): see Copywriting. The banner only renders when N > cap.
- Static tabs (Channels, Fees, Liquidity, Peers) show current state via AFM-001 latest-state reads — summary strip optional per planner, no window picker where a window is meaningless (Channels/Peers), window-aware where it is (Fees/Liquidity history if shown).
- Every table column head: Console-label role. Every numeric cell: mono tabular. Row hover: `hover:bg-card` (existing pattern).

### CSV export (NODE-02 — D-08, D-09, D-10)
- **"Export CSV"** Button (outline variant, Console-label typography, `Download` lucide icon at 16px) in each exportable tab's header row and in the cap banner. Exportable tabs: Channels, Forwards, Closes, Fees (minimum); others at planner discretion.
- Export scope = the **full selected window** (not the 500-row cap), bounded by the 90d max.
- File: provenance header comment rows (`# node alias+pubkey, table, window, exported-at UTC, data-as-of`) + formatted AND raw columns; filename `{alias}_{table}_{window}_{timestamp}.csv`. Mechanics (server route vs client blob) are planner discretion.
- Button states: default → busy ("Exporting…", disabled) → done (filename toast or silent download). No optimistic success copy before the file exists.

### Pending monitor (PENDING-01 — D-11, D-12, D-13)
- **Two surfaces, one component** (preferred per CONTEXT discretion): a `PendingBoard` parameterized by scope — fleet-wide at `/pending` (grouped by node), per-node in the console's Pending tab.
- **Grouped by type, age-sorted:** sections **Pending opens / Coop closes / Force closes**, oldest first within each. Sweeps nest indented under their parent force-close row. Section headings: Console-label role + count + the type's section marker dot (ok/warn/critical per the Color table). Empty sections collapse to a single quiet line ("No pending opens"), never hidden entirely on the fleet page.
- **Row contents (every row):** state · age (prominent — Heading-role mono, the pre-staged Phase-4 signal) · limbo/time-locked balance (AFM-002) · `broadcast_attempts` (sweeps). Age is prominent but **unjudged** — no red/yellow age thresholds this phase (D-13: display-only).
- **Fleet entry point (D-12):** a fifth **PENDING** block in the existing triage stat strip, linking to `/pending`. Dot lights (warn-yellow) only when count > 0; zero stays quiet grey like the other stats.
- Both surfaces carry the `FreshnessStamp` for the pending tables' data-as-of.

### Freshness (success criterion 4)
- **Every console tab and both pending surfaces** carry a `FreshnessStamp` (existing component, D-13 pattern) scoped to that view's source tables — placed in the tab panel's header row, right-aligned. Stale shows the existing `⚠ Stale` marker; stale data renders anyway, flagged.

### Responsive behavior
- Tab bar scrolls horizontally on narrow screens (`overflow-x-auto no-scrollbar`); active tab stays in view.
- Tables: `overflow-x-auto`; leading identity column (channel/peer) may be sticky.
- Summary strip wraps 5→3→2 cells down the breakpoints (grid, `gap-px` preserved).
- Pending rows stack their fields on mobile like `FleetRow` does (grid collapse pattern).

### States required (every tab + both pending surfaces)
- **Loading:** RSC `force-dynamic` server render (no client spinner for first paint). Any future client chart gets a fixed height.
- **Empty:** per-view copy below — always names the window/scope and the next step. Never a bare blank table.
- **Error:** per-view, Phase 2 pattern (problem + "this view is read-only" reassurance + next step).
- **Stale:** existing marker; data shown, flagged.

## Copywriting Contract

*Source: D-07 banner verbatim from CONTEXT; the rest follows the Phase 2 terse, fail-loud operator voice. Sentence case, active voice, no apology.*

| Element | Copy |
|---------|------|
| Primary CTA | **"Export CSV"** (per-table; the only action verb this phase — everything else is navigation) |
| Secondary CTAs | **"Open full console →"** (scorecard modal) · tab names: **Scorecard / Channels / Fees / Liquidity / Forwards / Closes / Peers / Pending** · window segments: **24h / 7d / 30d / 90d** |
| Cap banner | **"Showing newest 500 of {N} — Export CSV for the full window."** (renders only when N > cap; the count is the real N, mono tabular) |
| Empty state — event tab | Heading: **"No {forwards/closes} in this window"** · Body: **"Nothing recorded for {alias} in the last {window}. Try a wider window, or export a different range."** |
| Empty state — static tab | Heading: **"No {channels/peers} to show"** · Body: **"The warehouse returned no {channels/peers} for {alias}. If that's unexpected, check data freshness above."** |
| Empty state — Pending tab (per node) | Heading: **"No pending channels"** · Body: **"{alias} has nothing in flight. Pending opens and closes will appear here with state, age, and limbo balance."** |
| Empty state — `/pending` (fleet) | Heading: **"Nothing pending fleet-wide"** · Body: **"No pending opens, coop closes, or force closes on any node. New pending channels appear here, oldest first."** |
| Empty pending section | **"No pending {opens / coop closes / force closes}"** (single quiet line, Body role, muted) |
| Error state — any tab | Heading: **"Couldn't load {tab name}."** · Body: **"The warehouse didn't respond. Your data is unchanged — this view is read-only. Check the connection and reload."** |
| Export busy / failure | Busy: **"Exporting…"** · Failure: **"Export failed — the window query didn't complete. Try a shorter window."** |
| Stale marker | **"⚠ Stale — data as of {date}"** (existing, unchanged) |
| Freshness stamp | **"data as of {timestamp}"** (existing, unchanged) |
| PENDING triage stat label | **"Pending"** (count beneath, matching Critical/Warn/Healthy/Stale blocks) |
| Destructive confirmation | **N/A — Phase 3 has no write or destructive action.** Read-only by design; no confirmation flows exist. |

**Tone rules:** name the scope ({alias}, {window}) so empties are informative, not decorative; never present stale/missing data as authoritative; errors state the problem and the next step, no apologies; an action keeps its name through the flow (Export CSV → Exporting… → file lands).
