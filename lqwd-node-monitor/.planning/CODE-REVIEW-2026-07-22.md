# NodeMonitor — Comprehensive Code Review

**Date:** 2026-07-22
**Scope:** Entire project, read-only (no code modified).
**Method:** 7 parallel subsystem reviewers (Opus 4.8) → adversarial refutation pass on every HIGH/CRITICAL finding (drop-if-refuted) → synthesis.
**Result:** 1 CRITICAL, 5 HIGH (all survived adversarial verification), plus MEDIUM/LOW hardening and test-coverage items.

---

## Executive summary

The codebase is **disciplined and largely invariant-clean**. The adversarial pass actively tried to refute each severe finding and **confirmed all six**. The verified-clean surfaces are worth stating because they are the project's crown jewels:

- **DB read layer** — no `WHERE timestamp = MAX(...)` anti-pattern anywhere; every latest-per-entity read uses correct `DISTINCT ON`; all identifiers parameter-bound; fee math centralized through `feeMsatToSat`; three least-privilege clients correctly separated with `default_transaction_read_only` on both warehouses.
- **AI / narrative layer** — structurally command-free: `AiReadLine` has no `action`/`params` field; `narrate`/`narrateIncident` server-recompute and return model text verbatim with no parse-back into params. The AI-emits-no-commands invariant **holds**.
- **Export path (Prong 2)** — zero write path confirmed (no db/queue/crypto imports); every value reaching a runnable command is constrained by an anchored allowlist that cannot contain a shell metacharacter. No critical/high.

The severe findings cluster into **four themes**:

1. **Signature integrity gap (the big one).** The signing scheme binds `params`, `expiresAt`, and `nodePubkey` into the signed `canonical_payload`, but the node applies values read from the *separate, independently-mutable* `params` / `expires_at` columns — never re-deriving them from (or comparing them to) the signed bytes. This defeats the exact "tampered DB row" threat the HMAC exists to stop. (Findings Q1 CRITICAL, Q5 MEDIUM.)
2. **DB boundary doesn't enforce the state machine.** The executor role can `UPDATE ... SET state='approved'`; approved-only is enforced only in dashboard app code. (Finding Q2 HIGH.)
3. **Silent fleet mutation.** Fee cards ship a hardcoded `timeLockDelta: 80` that the node applies verbatim via `updatechanpolicy`, silently rewriting the CLTV delta of any channel not already at 80 — a direct hit on the "never silently mutates the fleet" core value. (Finding I1 HIGH.)
4. **Honest-stale erosion.** A Postgres day-roll silently loses the previous log file's unread tail (missed `FATAL`/`too_many_clients`), and honest no-data/stale STATE text is painted in the `df-faint` token that the codebase itself documents as failing contrast — the operator literally cannot read that a source has no data. (Findings C1 HIGH, U1 HIGH.)

Config controls are also silently ignored in two safety backstops (`NODEMON_RATE_LIMIT_MAX`, read-cap env tunables).

### Top 5 to fix first

| # | Finding | Why first |
|---|---------|-----------|
| 1 | **Q1 (CRITICAL) — node applies unsigned `params`/`expires_at` columns, not the signed payload** | Signature provides *zero* integrity for the values that reach `lncli`. A DB-write attacker with no HMAC secret changes an approved row's `params` in-bounds and the node applies it. Fix Q5 in the same change (derive `expiresAt`/`nodePubkey` from the signed payload too). |
| 2 | **Q2 (HIGH) — executor DB role can self-approve** | `nodemon_node` can flip `pending_approval → approved` at the DB; the operator-approval gate is bypassable without forging a signature. Enforce transitions with a trigger/policy. |
| 3 | **I1 (HIGH) — hardcoded `timeLockDelta: 80` silently rewrites channel CLTV** | Violates the core "never silently mutates" value; ships through bulk-enqueue with no operator edit. Omit `--time_lock_delta` (let lncli preserve) or read live policy node-side. |
| 4 | **C1 (HIGH) — Postgres day-roll loses the previous file's log tail** | Missed `FATAL`/`too_many_clients` reads as "no errors" — honest-stale violation on the exact PG-capture path COL-02/06 exist to feed. Drain `prev["path"]` directly on rotation. |
| 5 | **U1 (HIGH) — honest no-data/stale text rendered in illegible `df-faint`** | The most safety-relevant state (no data) is the least readable text on the board; fails WCAG 1.4.3 and the honest-stale invariant. Route state strings through `df-muted`/`df-stale-text`. |

## Test-coverage gaps (cross-subsystem)

- **Queue safety proofs are DB-gated.** `claim/enqueue/approve/state/stub-executor/withdraw` tests all require a live `nodemon` DB; in DB-less CI the atomic-claim/no-double-apply/TTL/reaper proofs silently don't run. Tag them "requires nodemon DB" and fail the deploy-gating pipeline if skipped. (Only `canonical/sign/bounds/ttl` run DB-less.)
- **No test for the Q1 params↔canonical binding** or a tampered-`params` node-side rejection (the code doesn't check it — the test would fail until Q1 is fixed, which is the point).
- **`hmac-vector.sh` tests an inlined copy** of `canonicalize`, not the shipped `canonical.ts`/`sign.ts` — real-module drift is invisible to the byte-identity proof.
- **No `update_fee`-params-satisfy-`updateFeeBoundsSchema` golden** (would catch I1/I3); **no malformed-pubkey fail-soft test** through detectors (I2).
- **No `narrate.test.ts`** (AI3); **no `df-faint`-on-content lint/test guard** (U1–U4); **no automated contrast check**.
- **Collector day-roll drain untested at the byte level** (C1 slipped through because the test asserts only the path change, not that the tail is drained); no test for `_drain_previous` (C2/C4), the OVERSIZE single-line drop, `_rls_admissible_node_rows`, or `collected_at` semantics; production `now` is TZ-aware but `grade_log_service` tests pass naive datetimes.
