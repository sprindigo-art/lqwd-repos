# Phase 16.2 — Confirmation Flow & L402 Fixes — Summary

## Why this phase existed

Phase 16.1 ("Gateway Safety Hardening") shipped with a UAT recorded as 7/7 passing, but the UAT was run in `GATEWAY_MOCK=true`. In mock mode `ConfirmOperation` short-circuits at `handlers.go:165-181` before touching the executor. A 4-agent code review on 2026-04-16 independently surfaced that the confirm → executor → LND chain was structurally broken in production.

Phase 16.2 fixed the broken chain, the related audit-filter bug, and two adjacent LLM-prompt-injection gaps, then proved it all against a real signet LND — specifically NOT in mock.

## What landed

### Code fixes

1. **CR-01 — JSON tag alignment** (`lnd-gateway/internal/lnd/client.go`). Handler structs serialize `push_sats` / `chan_id` / `address` / `amount_sats` / `fee_limit_sats`; the `lnd.OpenChannelRequest` / `CloseChannelRequest` / `SendCoinsRequest` / `SendPaymentRequest` structs that the executor unmarshalled into used `push_sat` / `channel_point` / `addr` / `amount` / `fee_limit_sat`. On confirm, every renamed field silently zeroed. Aligned tags to match handler shape. grpc.go consumes by Go field name, not JSON tag — so no behavior change on the LND-facing side.

2. **CR-02 — Missing executor case for `/v1/payments/send`** (`lnd-gateway/internal/lnd/executor.go`). Phase 16.1 added confirmation gating to SendPayment but never wired the executor case. Every admin-confirmed payment returned `"unknown endpoint for execution"`. Added the case.

3. **CR-03 — `DailySpend` op_type filter mismatch** (`lnd-gateway/internal/handlers/handlers.go`). ConfirmOperation was writing `OpType: "confirmed_" + op.Endpoint` but `audit.DailySpend()` filters `op_type IN ('payment','channel_open','onchain_send','rebalance')`. Zero matches; the post-hoc kill switch saw zero outflow. Added `endpointToOpType()` helper that maps each confirmation endpoint to its canonical op_type. Preserved the "this came from a confirmation" signal by prefixing the `Endpoint` field (not `OpType`) with `confirmed:`.

4. **P-3 — Rebalance bypassed confirmation** (`lnd-gateway/internal/handlers/analytics.go`). Refactored to mirror SendPayment: budget check → `Confirm.Create` → 202 Accepted. Added `/v1/rebalance` to the executor switch and the `endpointToOpType` map.

5. **P-4 — RestartLND was agent-callable** (`lnd-gateway/cmd/lnd-gateway/main.go`). Wrapped with `middleware.RequireAdmin` like every other `/v1/admin/*` endpoint.

6. **CR-04, CR-05 — L402Pay idempotency + refund** (`lnd-gateway/internal/handlers/l402_client.go`, `internal/idempotency/store.go`). Added `Idempotency.Store` after success; added a new `Idempotency.Release()` that deletes only pending reservations (status_code=0) so callers can retry after pre-payment failures; on post-payment failures, store the error with a receipt so retries surface the outcome instead of double-paying.

### Config changes

- **`FAUCET_CHANNEL_SIZE_SATS`** default: 100_000 → **20_000** (LND minchansize floor)
- **`FAUCET_PUSH_SATS`** default: 25_000 → **1_354** (1,000 spendable + 354-sat p2wsh dust/reserve)
- **`SETUP-GUIDE.md`** mainnet `minchansize=2000000` → **20000** (was blocking 20k faucet opens)

### Tests added (17 new)

All failure modes now caught in CI without needing a live signet.

- `internal/lnd/executor_test.go` — 4 `TestExecutor_HandlerShape_*` tests that replay the literal JSON each handler emits and assert the deserialized request carries the right fields. Catches any future JSON tag drift.
- `internal/lnd/executor_test.go` — `TestExecutor_SendPayment` for the new case.
- `internal/handlers/confirm_optype_test.go` — `TestEndpointToOpType` (table) + `TestConfirmOperation_WritesCanonicalOpType` (table over all 5 endpoints) + `TestConfirmOperation_DailySpendIncludesConfirmedPayments` (end-to-end DailySpend regression).
- `internal/handlers/analytics_test.go` — `TestRebalance_MockSuccess` replaced with `TestRebalance_RequiresConfirmation` (pins 202 + confirmation_required=true + queue count). `TestRebalance_Idempotency` pins first-call 202.
- `internal/idempotency/release_test.go` — 3 tests: releases pending reservations, preserves completed responses (data-loss guard), empty-key no-op.
- `internal/handlers/l402_client_idempotency_test.go` — `TestL402Pay_MockMode_StoresIdempotencyResponse` regression test for CR-04.

## Pre-existing prod bugs discovered during UAT (not 16.2 regressions, but fixed)

Both surfaced because signet UAT exercised real LND paths that the prior mock-only UAT skipped.

- **`pay.macaroon` missing `onchain:write`** — Every on-chain send in production would have returned `permission denied`. `SendCoins` uses `c.macaroons.Pay` (grpc.go:506). SIGNET-SETUP.md Step 8 baked the pay macaroon with only `offchain:read offchain:write`. Rebaked on both signet and mainnet. `SIGNET-SETUP.md` and `SETUP-GUIDE.md` should be updated to include `onchain:read onchain:write` in the pay macaroon bake for new deployments.
- **`/lnd/lnd.conf` had stale `minchansize=2000000`** — 20x the new faucet default. Would have rejected every faucet open with a vague "chan size below minimum" error from LND. Changed to 20000 and restarted LND.
